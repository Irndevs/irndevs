Por que todo projeto Python precisa de venv

IRN Devs · 2026

Instalar pacotes globalmente no Python do sistema é o caminho mais rápido para conflitos, upgrades quebrados e “funciona na minha máquina”. O venv resolve isso com três linhas.

O problema

Dois projetos pedem versões diferentes da mesma biblioteca. Sem isolamento, um sobrescreve o outro. Em servidores, o Python do SO é usado por ferramentas do próprio sistema — poluí-lo é risco operacional.

A solução em 30 segundos

python3 -m venv .venv
source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt

No Windows PowerShell: .venv\Scripts\Activate.ps1.

Boas práticas

  • Sempre pin versions no requirements.txt (pip freeze)
  • Coloque .venv/ no .gitignore
  • Em Docker, o próprio container já isola — ainda assim use venv se preferir
  • Documente no README o comando de ativação
