Como montar um portfólio no GitHub que atrai recrutadores

IRN Devs · 19 set 2026 · 8 min · carreira

Recrutadores de tech abrem o GitHub em segundos. Se a página parecer abandonada ou confusa, a chance de avançar cai. O bom é que dá para melhorar isso em um fim de semana.

1. Foto, bio e pin de projetos

  • Foto profissional (mesmo que casual e bem iluminada)
  • Bio com o que você faz + o que busca (ex.: “Dev Python · automações e APIs · aberto a oportunidades remotas”)
  • Pin 4–6 repositórios que mostram variedade e profundidade

2. README do perfil (profile README)

Crie um repositório com o mesmo nome do seu usuário. O README vira a capa do perfil. Inclua: quem você é, stack, 2–3 projetos em destaque com link e uma seção “como entrar em contato”.

3. Cada projeto precisa de README de verdade

Não basta o código. Todo repositório público sério deve ter:

  • O que o projeto faz (1 parágrafo)
  • Como rodar localmente (comandos copiáveis)
  • Stack e pré-requisitos
  • Screenshot ou GIF se for interface
  • Licença (MIT é o mínimo comum)

4. Commits legíveis

Evite “update” e “fix”. Prefira mensagens no estilo: feat: validar CPF no formulário de cadastro. Histórico limpo mostra profissionalismo.

5. Projetos que impressionam (sem inventar)

  • API com autenticação e documentação (OpenAPI/Swagger)
  • Automação que resolve um problema real (planilha, e-mail, scraping ético)
  • Deploy público (Vercel, Railway, VPS) com URL no README

Checklist rápido

[ ] Bio e localização preenchidas
[ ] 4+ repos pinados com README completo
[ ] Profile README com stack e contato
[ ] Pelo menos 1 projeto deployado
[ ] Activity recente (commits nos últimos 30 dias)
